# H0 — 腹面の摩擦クーポン（前後 / 後ろ / 横 の摩擦と、横/前後の比）

目的: **Pure Snake Locomotion を続けるか、Wheel Belly に戻すか**を、家の床の実測で決める材料を作る。
根拠: EXP-ENG-0001（`ai-outbox/experiments/2026-09-29_EXP-ENG-0001_fw_body_sensitivity.md`）。MuJoCo では推進の成否が横/前後の摩擦比で決まり、しきい値は約 1.5〜2.5 だった（PHYSICS_SIM）。

測った摩擦係数そのものは、日付・条件・道具を記録すれば **HARDWARE_VERIFIED（クーポンと床の組み合わせに限る）** になる。
それを入れた推進の予測は **PHYSICS_SIM のまま**（実機の走行ではない）。

## 1. 印刷するもの

`tools/h0_coupons.py` で STL を作る（`hardware/prototypes/H0_friction/stl/`。git には入れない）。

| ID | 形状 | 下面（床に当たる面） | 見たいこと |
|---|---|---|---|
| FLAT | 60 × 40 × 4 mm | 平ら。外周 3 mm を丸めて持ち上げる | 材料だけの差（PETG / TPU） |
| SCALE | 同 | 横向きの非対称のこぎり歯（ピッチ 3 mm、深さ 0.6 mm、前へ緩い斜面） | 前へ滑り、後ろへ引っかかるか（鱗の向き） |
| KEEL | 同 | 前後方向の三角の畝（ピッチ 4 mm、高さ 0.8 mm） | ラグ・カーペットで横ずれを止めるか |

上面に彫った矢印 = **機体の前（+x）**。

**第 1 ラウンドで印刷する 4 個**（全部やると 270 回の測定になるので絞る）:

| クーポン | 材料 |
|---|---|
| FLAT-PETG | PETG |
| FLAT-TPU | TPU（95A 程度。銘柄と硬さを記録） |
| SCALE-PETG | PETG |
| KEEL-TPU | TPU |

印刷の注意:
- **上面（矢印の面）をベッドに付けて、裏返しで印刷する。** 模様の面が上に来るので、サポートは要らない
- 上面の積層線の向きは摩擦の異方性を作る。**スライサーの top surface pattern を記録する**（できれば concentric）。ironing は使わない（使ったら記録）
- ノズル 0.4 mm、層 0.2 mm を推奨。プリンタ（A1 / K1 Max）・材料の銘柄・色を CSV に書く

## 2. 道具

- 板（30 × 60 cm 程度の平らな板。ラグ・カーペットの切れ端を載せて傾ける）
- スマホの傾斜計アプリ（角度 0.1° 表示のもの）、または分度器
- おもり: クーポン込みで **150 g**（胴 1 節ぶんの荷重の目安。ASSUMPTION）。硬貨や小袋の砂を両面テープで上面の中央に貼る。キッチンスケールで量る
- （任意）デジタルの吊りばかり。実際の床で引っ張る方法（方法 P）に使う

## 3. 測り方

### 方法 T（傾斜法。主にこれを使う）

1. 板に床材を載せ、水平（0°）にする。フローリングは同じ仕上げの板材か端材で代用する（**代用したら CSV の floor_note に書く**）
2. クーポンを置く。向きは **前向き（矢印が坂の下）/ 後ろ向き（矢印が坂の上）/ 横向き（矢印が坂と直角）** の 3 通り
3. 板の片端をゆっくり持ち上げ（1 秒に 1° 程度）、**クーポンが滑り始めた角度 θ** を読む。μs = tan θ
4. 1 条件 3 回（ばらつきが大きければ 5 回）。回ごとにクーポンを置き直す。床の同じ場所を使いすぎない

「前向き」は、機体が前へ進むときに床と腹がこすれる向き（クーポンが +x へ滑る）。坂の下に矢印を向けて置くと、クーポンは +x へ滑る。

### 方法 P（引っ張り法。実際の床で確かめたいとき）

クーポンに糸を付け、吊りばかりで床と平行に、ゆっくり一定の速さで引く。動き出す瞬間の最大値（静）と、動いている間の値（動）を読む。μ = 力 / 荷重。
荷重 150 g だと力が 30〜100 g 程度と小さいので、はかりの分解能を CSV に書く。

### 方法 D（45° の滑り方向。**摩擦法則の形を決める。いちばん情報価値が高い**）

クーポンの矢印を、坂の下向き（または引く向き）から **45°** 回して置き、滑らせる。滑った向きとクーポンの軸（矢印）のなす角を読んで
`direction = diag45`、`slide_track_deg` に書く（0 = 軸に沿って滑った）。跡はクーポンの角に付けたチョークの粉か、真上からの動画で読む。
理由と予測値は `simulation/hardware_gaps/HG-H0_friction/hardware_test_plan.md`（T3）。

## 4. 条件（シミュレーションで絞った最小の組。2026-09-29 更新）

| 測定 | 回数 | 備考 |
|---|---|---|
| 前向き（forward） | 3 床 × 4 クーポン × 3 回 | 必須 |
| 横向き（lateral） | 3 床 × 4 クーポン × 3 回 | 必須。左向き / 右向きを交互にして note に書く（左右の差を見る） |
| 45°（diag45、方法 D） | 3 床 × 最良のクーポン 1 × 3 回 | 必須 |
| 後ろ向き（backward） | 3 床 × 4 クーポン × **1 回** | 鱗の向きが逆でないかの確認だけ（前進にはほぼ効かないことが分かった） |
| 引っ張り法（P、動摩擦） | 3 床 × 最良のクーポン 1 × 前 / 横 × 3 回 | 静止と滑りで比が変わるかを見る |

| floor_id | 床 | 記録すること |
|---|---|---|
| WOOD | フローリング | 仕上げ（ワックス・コーティング）、代用品かどうか |
| RUG | ラグ | 毛足の長さ mm、素材、毛の向き（撫でる向きと測る向きの関係） |
| CARPET | カーペット | 同上 |

## 5. 記録

`h0_friction_template.csv` をコピーして 1 行 1 回で書く。空欄は空のまま（推測で埋めない）。

## 6. 解析（主）

```
.\.venv\Scripts\python.exe simulation\hardware_gaps\HG-H0_friction\run.py --measured hardware\prototypes\H0_friction\h0_friction_YYYYMMDD.csv
```

生データの控え → 検証 → 当てはめ（比の 95% 区間、45° 試験から法則の推定）→ 5 構成で再計算 → 床ごとの読み
（HEAD_YAW_OK / BODY_YAW_NEEDED / SNAKE_INSUFFICIENT）→ Handoff まで自動。判定は**提案であって正式 Decision ではない**。

`tools/h0_friction.py`（MuJoCo で前進を予測する旧版）は照合用に残す。MuJoCo は前後の差と法則の形を表せない。

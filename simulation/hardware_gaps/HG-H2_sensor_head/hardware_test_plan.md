### (a) GPIO 割り当ての確認（K-0001 (1)）

一次資料（Seeed Studio Wiki「Getting Started with Seeed Studio XIAO ESP32S3 Series」、2026-10-01 に確認）: D0〜D10 = GPIO1 / 2 / 3 / 4 / 5 / 6 / **43 / 44** / **7 / 8 / 9**。Sense の microSD = CS GPIO21・**SCK GPIO7・MISO GPIO8・MOSI GPIO9**、カメラ = GPIO10〜18・38〜40・47・48。3V3 ピンは「700 mA」と記載、**5V ピンの電流能力は記載なし**。
- K-0001 の割り当て（D0〜D5 = GPIO1〜6、D6・D7 = UART 予約、D8・D9 = ToF の GPIO1 への 0 Ω リンク（DNP）、D10 = 未使用）は、**カメラのピン（GPIO10〜18 など）と重ならない**。
- **D8・D9・D10（GPIO7・8・9）は microSD の SCK・MISO・MOSI と共用**。K-0001 は D10 を未使用にしているので、**microSD を使うなら D8・D9 のリンクは外したまま（既定のまま）**、D10 には何もつながないこと。microSD を使わないなら ToF の GPIO1 へのリンクは使える。
- GPIO3（D2）はストラッピング ピン（JTAG の信号源の選択。ESP32-S3 データシート §3.4）。K-0001 の「100 kΩ で L に固定。eFuse 既定なら無視される」は妥当。**LEDC の PWM 周波数は、人の耳に聞こえない帯（20 kHz 以上）か、LED のちらつきが撮影の露光と干渉しない周波数**にする（撮影の露光時間との位相が影の濃さを変える。ファーム側の注意）。
- 頭の XIAO のファームは**このリポジトリに無い**（`firmware/` は胴の ESP32-S3 `serpens_esp32` だけ）。上はファームを書くときの前提。

### (b) T4「斜めの明るさ × k」の k = 1.0 が何 mA か（K-0001 (3)(b)）

**定義されていない（mA には結びついていない）**。HG-H2 の合成では、k は `Lighting.raking_lux`（床の照度。既定 **200 lux = ASSUMED**）に掛ける倍率で（`led_layout_recheck.py`: `raking_lux × scale`）、LED の電流・光束・配光・距離とは対応づけていない。環境光は 8 lux（nominal）。
- **条件つきの読み**: K-0001 の 3V3・20 Ω 駆動の 1 個あたり光量 11 / 30 / 49 %（80 mA 時の光量に対する概算）を、**仮に「k = 1.0 = 80 mA 時」と置く**と k = 0.11 / 0.30 / 0.49。`tof_cliff.md` §4 の結果（斜め × 0.5 で巡回 0.89、× 0.25 で 0.36、× 0.12 で 0.02）に重ねると、**3V3 駆動の最小側（k ≈ 0.11）では巡回の影の検出が落ちる側**、最大側（0.49）なら保てる側。5V・33 Ω 駆動（56 / 74 / 91 %）なら全部保てる側。
- **ただし、この対応は仮定**（200 lux が 80 mA 時に相当する根拠が無い）。確かめる方法: T4 で、LED の電流（TP の電圧 1 mV = 1 mA）と、**床の照度（照度計。スマホの照度アプリは粗い目安）**を同時に記録し、200 lux に相当する電流を実測で決める。結果が出るまで、**T4 の結果は「3V3・20 Ω 駆動」または「5V・33 Ω 駆動」の条件つきで読む**（K-0001 の依頼どおり）。
- 巡回の影の検出は、斜め照明の明るさが約 1/4 を下回ると落ちる（合成）。**LED の電流を設計の余裕で選ぶときは、3V3 の最小側（11 %）を使わない**ほうが安全側（実測が出るまでの方針。Engineering の提案。基板の変更は KiCad 側の判断）。

### (c) XIAO Sense の 5V 入力電流（K-0001 (c)）と、同時動作の運用上の注意（K-0002 (3)②）

- **実測の項目を HARDWARE_TODO に追加した: HT-015**（Wi-Fi 送信・撮影・LED・ToF のピーク。電流制限つきで、同時は最後）。Seeed のカメラ表の MAX ≒ 0.65 A は測定条件の記載なし = 未確認で、3V3 の「700 mA」と合わせると、同時にすべて最大にすると余裕が無い（K-0001 (4): 808 mA = 115 %）。
- **運用上の注意を T4 / T6 の手順に入れる**（K-0002 (b)。**安全側に倒す変更なので採用する**）: **3V3 駆動では、Wi-Fi 送信・撮影・LED 100 %・ToF のピークを同時にしない**。T4 では、(1) LED の点灯と撮影の露光を同時にする場合も **Wi-Fi 送信は撮影が終わってから**（撮影 → 保存 → 送信の順）(2) LED の PWM は 100 % にしない（上限を設ける。値は HT-015 の結果で決める。それまで 50 % 以下を試験の既定にする）(3) ToF の測距は撮影の露光中は止めるか、間隔を空ける。
- 5V 駆動を試す場合は、USB 2.0 の 500 mA 以内（K-0001: 合計 493 mA、余裕 7 mA）を超えないように**電流制限 500 mA** をかける。

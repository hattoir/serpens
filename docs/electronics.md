# 電子系 — ブロック図・電力の見積もり・部品表の骨格（設計案。HARDWARE_UNVERIFIED）

作成 2026-09-18。**回路図も基板も部品も無い。** この文書は `ELECTRICAL_SAFETY_GATE`
（`docs/safety_limits.md` §5）の 8 項目を「何をどう測れば埋まるか」まで落とすための骨格。
数値は出典を書く。出典が無いものは **UNKNOWN** のまま置く（推定で埋めない）。

## 1. ブロック図（案）

```
[12V テザー] ─ ヒューズ ─ [電源分配]
                             ├─ DC/DC 5V ─ [XIAO ESP32-S3]（駆動リンク・歩容・watchdog）
                             │                 │ UART 1M bps（半二重）
                             │                 ↓
                             ├─ **遮断器** ─ [サーボバス V+] ─ STS3215 ×9（デイジーチェーン）
                             │      ↑
                             │   [安全 MCU or ハード watchdog]  ← 物理 E-STOP（直列・常閉）
                             │      ↑                              ← 電流検出（バス全体）
                             │   ESP32 の「生きている」パルス（heartbeat 出力）
                             └─ DC/DC 5V ─ [頭部 XIAO]（ToF・タッチ・LED。既存の行プロトコル）
```

要点（憲章 16章 層2）:

- **サーボの電源を切る経路を ESP32 に依存させない。** 遮断器（リレー or ハイサイド MOSFET）は
  安全 MCU（またはリトリガ型ハード watchdog）が駆動し、ESP32 のパルスが止まれば切る。
  ファームが暴走しても、PC が死んでも、電源が落ちる。
- **物理 E-STOP は遮断器の駆動回路に直列**（ソフトを介さない）。常閉接点で、抜けても止まる側へ。
- 電流検出はバス全体で 1 箇所（まず十分）。閾値は実測後（§2）。
- 12V → サーボ V+ の間に **C044 の最高入力電圧（8.0V 初期値。`docs/sts3215_registers.md`）に合う電圧**
  が要る。12V を直結してはいけない。7.4V を作る DC/DC（容量は §2 の実測後）か、電源そのものを変える。

## 2. 電力の見積もり — 出典ごとに分ける

| 値 | 数値 | 出典 | C044（7.4V / 1:191）に使えるか |
|---|---|---|---|
| ST3215 入力電圧 | 6〜12.6V | Waveshare Wiki ST3215_Servo（2026-09-18 閲覧） | 電圧範囲は同型番の記載。**C044 の上限は要確認** |
| ST3215 ストール電流 | 2.7A | 同上（電圧の記載なし。30kg·cm@12V の品） | **使えない**（12V 品の値） |
| ST3215 無負荷電流 | 200mA | 同上 | **使えない**（同上） |
| C044 ストール電流 / 無負荷電流 / 待機電流 | **UNKNOWN** | 一次資料なし | 実測で埋める |
| 定格トルク（参照） | 5.2 kgf·cm | CAD 資料（`config/robot.yaml` servo） | 参照値。実測ではない |

**だから電源容量・ヒューズ定格・遮断閾値はまだ決められない。** 決めるのに要る実測:

1. C044 1 個の無負荷電流・保持電流・ストール電流（7.4V、電流計直列）→ `real_current`
2. 9 個の同時起動時の突入電流（オシロ + シャント）→ `power_capacity`
3. 歩容（FAST / SMOOTH の候補）を模擬負荷で 10 分回したときの平均・ピーク電流と配線温度 → `wiring_heat`

見積もりの**枠だけ**書くと（値は入れない）:
`I_supply ≥ N × I_stall(C044)` が最悪、`I_typ ≈ N × I_hold + 歩容の変動` が通常。
ヒューズは `I_typ` の余裕上、`I_supply` の下。すべて実測後に埋める。

## 3. ゲートの各項目をどう埋めるか

| ゲート項目 | 測り方 / 作り方 | 必要な物 |
|---|---|---|
| real_current | §2 の 1 | C044 ×1、7.4V 電源、電流計 |
| power_capacity | §2 の 2 | C044 ×9、シャント、オシロ |
| overcurrent_protection | 意図的にストールさせ、ヒューズ/電子遮断が**実際に**切れることを見る | ヒューズ or 電子遮断の候補 |
| wiring_heat | §2 の 3。コネクタ温度を熱電対で | 熱電対 |
| independent_power_cut | §1 の遮断器を作り、ESP32 のパルスを止めて切れることを見る | 安全 MCU or watchdog IC、リレー/MOSFET |
| physical_estop | 押したら遮断器が切れる。ケーブルを抜いても切れる（常閉） | E-STOP スイッチ |
| servo_temperature | 連続運転で温度レジスタ（番地 63）と実温度を比べ、60℃ で機体が止まることを見る | 熱電対 |
| real_stop_time | 緊急停止・通信断から出力が止まるまで。オシロでサーボ電流 or 位置を見る | オシロ |

### 6.1 prior から出た設計上の制約（実測で置き換わる）

1. **サーボの電源の線は「保持 + 歩容」だけでも太い**: 幹線の実効電流 p95 ≈ 8.6 A（MVP）に対し、ΔT ≤ 20 K で流せるのは AWG24 約 2.2 A / AWG22 約 2.8 A / AWG20 約 3.6 A（prior）。→ **幹線を 1 本にせず、軸ごとの枝（または太い幹線 + 短い枝）**にする。
2. **電流の閾値だけでは「歩容のピーク」と「ストール」を分けられない**: 歩容のピーク p95 11.9 A と全軸ストール p50 10.5 A が重なる。設定電流 T = 5 A でも通常動作で誤って切る確率 0.75（prior）。→ **合計電流の 1 つの閾値を主の保護にしない。** 主 = 軸ごとの電流・温度（サーボのレジスタ + 機体側 60 ℃）、**ヒューズ / 電子遮断は配線を守る最後の砦**（配線の許容電流の少し上、時間特性つき）。
3. **電源の遮断経路の時間**: リレー + 出力の低下は p50 25 ms・max 45 ms（prior）。**リレーでは 20 ms（要求は未確定）に届かない確率が高い**。→ 遮断は **MOSFET のロードスイッチ（ゲートを引き抜いて切る）**を第一候補に（出力コンデンサの放電経路を設ける）。実測 = HA-E-02 / HA-E-08。
4. **電圧**: 2S 満充電 8.4 V はレジスタ 14 の初期値 8.0 V を超える。→ 7.4 V に降圧するか 7.4 V で止まる電源（EC9）。**レジスタを上げて合わせる（保護を緩める）案は採らない。**
5. **電源の全抵抗**: 7.4 V で R ≤ 0.12 Ω（MVP、prior）。コネクタ・ヒューズ・MOSFET の Rds(on)・配線の合計で見る。

### 6.2 ブロック（MVP 5 軸、頭は別）

```
[電源: 12V テザー（降圧 7.4V）or 2S] ─ ヒューズ（配線保護の最後の砦）─┬─ [電流センサ（バス全体の測定。保護ではなく記録）]
                                                                    └─ [MOSFET ロードスイッチ] ─ 枝 ×5 ─ STS3215 ×5
                                                                             ↑ enable
        [物理 E-STOP（常閉・直列）] ─ [独立の監視（watchdog IC or 小型 MCU）] ← heartbeat（ESP32 の GPIO パルス。止まれば切る）
                                                    ↑ 過電流・過熱の比較器（任意。ハードで切る）
[降圧 5V] ─ [駆動の ESP32] ─ UART（半二重。Waveshare Bus Servo Adapter か方向制御つき） ─ サーボバス
[降圧 5V / 3V3] ─ [頭の XIAO]（K-0001 の基板。電源は別系統でも可。EC8）
```

- **E-STOP は enable の直列**（ソフトを介さない）。常閉・直接開離型。**線が切れても、抜けても切れる側**。
- **監視は ESP32 に依存しない**。heartbeat が止まる / E-STOP が開く / 比較器が働く → ゲートを引き抜く。**再投入は自動にしない**（ラッチ。CLEAR_FAULT → DISARMED → 明示 ARM の段差と同じ考え）。
- 電流センサ（INA226 級: I2C、シャント電圧 ±81.92 mV。**データシート未確認**）は**測定と記録**（HA-E-01 / 02 の取り込み口 `current` / `power_sag`）。保護の主にはしない（6.1 の 2）。

### 6.3 選定基準（品番は選ばない）

| 区分 | 基準 | 状態 |
|---|---|---|
| ヒューズ / 電子ヒューズ | 配線の許容電流（6.1 の 1）の少し上、ストール電流（HA-E-01 の実測）より下、**時間特性（突入を通す）**。配線ごと | 未選定。C044 のストール電流が UNKNOWN |
| MOSFET ロードスイッチ | Rds(on) × 電流で全抵抗に効く（6.1 の 5）、電流定格 > ストール（実測）、ゲートを速く引き抜ける、**出力の放電経路** | 未選定 |
| 独立の監視 | 電源投入時は**切れた状態**で始まる、heartbeat の周波数（制御周期 100 Hz と合わせる）、E-STOP 入力、ラッチ | 未選定（watchdog IC か小型 MCU か = 設計の判断。MCU は賢いがファームが増える）|
| 物理 E-STOP | 常閉・直接開離、人が押しやすい位置と大きさ（**見た目は Design の OPEN-007**）| 未選定 |
| 降圧 | 7.4 V（またはレジスタ 14 を上げない範囲）、容量は HA-E-01 の後、起動時の突入に耐える | 未選定 |
| 電流センサ | 測定範囲 ≥ ストール（実測）、シャントの発熱 | 未選定 |

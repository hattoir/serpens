# Phase 3B — 3D 物理シミュレーションの選定

作成 2026-09-15。**まだ導入していない。** この文書は「何を基準に選ぶか」と「どう入れるか」の検討。
Phase 3A（軽量シミュレーション + 仮想 ESP32 + 仮想サーボ）が安定してからの作業。

## 0. 何のために要るのか

いまの 2D シミュレータ（`serpens/sim/world.py`）は、**接地点の非ホロノミック拘束を
重み付き最小二乗で解く**だけのもの。速くて決定的で、行動の試験には十分だが、
次の問いには**原理的に答えられない**:

| 問い | 2D シミュレータ | 3D 物理 |
|---|---|---|
| 鎌首（J7 で頭を持ち上げる）で転倒しないか | 答えられない（重力も転倒も無い） | 答えられる |
| Snake Belly で本当に進むのか | 摩擦の重みを仮定しているだけ | 接触力から出る |
| 各関節に何 N·m 必要か | 出ない（トルクの概念が無い） | 出る |
| 自己干渉したときに何が起きるか | 干渉「したか」しか分からない | 接触力が出る |
| 段差・絨毯 | 無い | 作れる |
| 消費電力 | 代用値（関節速度の総和）だけ | トルク×角速度で推定できる |

特に**トルクの推定**は、サーボ選定（12V 1:345 か 7.4V 1:191 か）と
安全のトルク上限（`docs/safety_limits.md`）に直結する。

## 1. 候補の比較

要件: Python から回せる / pip で入る / **オフラインで動く** / 異方性摩擦 / 自己衝突 /
決定的（テストに使える）/ 依存が重すぎない / ライセンスが明快。

| | MuJoCo | PyBullet | Gazebo (Ignition) | Drake | Isaac Sim |
|---|---|---|---|---|---|
| 導入 | `pip install mujoco`（本体同梱） | `pip install pybullet` | 別インストール、ROS 寄り | `pip install drake`（大きい） | NVIDIA GPU 必須・巨大 |
| ライセンス | Apache-2.0 | zlib | Apache-2.0 | BSD | 商用条件あり |
| **異方性の滑り摩擦** | **ネイティブ**（接触ごとに5係数: 接線2・ねじり1・転がり2。接線の2方向に別の値を入れられる） | 基本は等方（`lateralFriction` + 異方性方向の指定はあるが扱いにくい） | 可（ODE/DART 依存） | 可 | 可 |
| 自己衝突 | 可 | 可 | 可 | 可 | 可 |
| 決定性 | 高い | 中（設定依存） | 中 | 高い | 低め |
| 保守 | Google DeepMind、毎月リリース | 保守は緩やか | 活発（ROS 2 圏） | 活発 | 活発 |
| ヘビ型の実績 | 研究で多い | 多い | 多い | 少ない | 少ない |

**この機体にとって決定的なのは異方性摩擦**（Snake Belly の鱗は「前後に滑り、横に滑らない」ことで
推進するので、等方摩擦しか持てない物理エンジンでは Snake Belly の是非を判定できない）。
MuJoCo は接触ごとに 5 つの摩擦係数を持ち、接線の 2 方向に別々の値を入れられる
（公式文書いわく「skating のような効果を表現できる」）。

→ **MuJoCo を第一候補とする。**

## 2. どう入れるか（依存を増やしすぎない）

- **`serpens/` 本体から import しない。** MuJoCo は `tools/` からだけ使う**任意**の依存にする。
  `requirements.txt` には入れず、`requirements-sim3d.txt` を別に置く。
  → モックファースト（実機もGPUも無しで全機能が動く）と、オフライン起動を壊さない。
- **モデルは `config/robot.yaml` から生成する。** MJCF（XML）を手で書くと、
  可動域・リンク長・質量が config とズレる（ファームで実際に起きた）。
  生成器 `tools/make_mjcf.py` を作り、`tests/test_firmware_sync.py` と同じ考えで
  **生成物と config の一致を自動検査**する。
- **2D シミュレータは残す。** 行動の試験は 1 ステップ 10ms 以下で回る必要がある
  （`test_behavior_sim.py` は 1 本 27 秒）。3D は「問いに答える道具」であって、
  日常の回帰試験を置き換えるものではない。

## 4. 気をつけること

- **3D になっても現実ではない。** 摩擦・慣性・サーボの応答は依然として仮定。
  `docs/verification_status.md` の区分で言えば `SIMULATED` のまま。
  実機が来たら `tools/fit_sim.py` と同じやり方で係数を同定する。
- **受動輪のモデル化が難所。** 転がり抵抗だけを小さくした異方性摩擦で近似するか、
  回転ジョイント付きの円柱を 14 個置くか。後者は接触が増えて遅くなる。まず前者で始める。
- **GPU は要らない**（MuJoCo は CPU で動く）。MJX（GPU 版）は当面不要。

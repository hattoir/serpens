# Lessons — Design Run DESIGN-2026-09-29-01

1. **1 つの作業ツリーで 2 つの Agent が別ブランチを使うと、HEAD を取り合う。** Design と Engineering が同じ `serpens/` で checkout し合い、
   Engineering の 2 コミットが main に入った（ENTRY-0004）。Agent ごとに `git worktree` を分けるのが安全。共有の状態ファイル（ai-shared）は未追跡のまま共有ツリーに置く
2. **Fusion の API スクリプトに日本語の文字列リテラルを書くと文字化けする**（UTF-8 が別の符号として読まれ、名前の比較が失敗・外観の色が付かない）。
   外観はライブラリの id（例 `Prism-127` = プラスチック マット白）で取り、名前は ASCII にする
3. **Fusion の as-built ジョイントが動かない時は `isGroundToParent` を見る。** 最初に作ったコンポーネントが親に固定されていて、別の節を固定すると間の関節が全部動かなくなった
4. **センサーの位置を顔の造作に割り当てるときは、光の通り道まで計算する。** 眉のライン光を顔の面から 10 mm 下げる案は、鼻先が近い床（38〜48 mm）への光を遮っていた（側面視の計算で発見）
5. **2D の図より、3D で横から見ると印象が変わる。** 背板を胴より 2 mm 厚くしただけで「屋根の板」に見えた。形の判断は Fusion の側面・正面でも確かめる
6. **関節の隠し方は、中の部品の持ち主（どちらの節と一緒に回るか）まで決める。** 同心ナックルは形だけなら成立するが、関節の後ろの空間の持ち主が変わり、電装の位置と衝突した（ENTRY-0011）
7. **Fusion の正投影カメラ: 透視から切り替えた直後の 1 回目は `viewExtents` が無視される**（画面いっぱいに 1 色の絵になる）。カメラを 2 回代入し、`vp.camera.viewExtents` を読み返してから保存する
8. **Fusion の MCP は 1 回の呼び出しで描き出し 30 枚前後を超えると時間切れになる。** 時間切れでもスクリプトは最後まで走ることがあるので、ファイルの時刻で確かめてから再実行する
9. **自分で作った評価モデルは、図にして形を確かめてから数値を採る。** J1 の 2D 検討で、首の前面・首の上の切り方・角度の折り返しの誤りを図で 3 回見つけた
10. **Fusion の入れ子の occurrence は API で平行移動できない**（`transform2` は「root の proxy のみ」、Move feature も入力を拒否）。部品を離して置く必要があるなら、最初から別の位置で作るか、部品を root 直下に置く
11. **ユーザーパラメータ → スケッチ寸法の式（`-tip_x` 等）で、数値の変更が形に追従する。** 追従することを実際に値を変えて確かめる（hinge_h 12.0 → 12.3 で腕が動き干渉が 0 になった）。最小肉厚の違反（ボス壁 1.1 < 1.2）も式（穴 + 2 × wall_min）で直せた
12. **スクリプトが時間切れでも最後まで走ることがある。** 読み取り専用の状態確認（本数・体積・bbox）で完了を確かめてから再実行する。60 秒に収めるには、特徴量の多い部品を 2 本のスクリプトに分ける
13. **Fusion で `body.deleteMe()` をすると、その体から作った後続のフィーチャ（分割・交差）ごと消える。** 尾の帯を「コピー → ブーリアン → 新規追加 → 元を削除」で直そうとして、背中の 3 つの体（セージ・ストライプ）が消えた（タイムライン 557 → 554）。復旧は保存版を開き直し。**既存の体を直す時は、押し出しの切り取り（`participantBodies` で相手を指定）を使う。**
14. **XZ 平面のスケッチは、スケッチの +y が world の −Z に向く**（このドキュメント）。`sketchToModelSpace` で 1 点を変換して符号を確かめてから寸法を入れる
15. **`OrientedBoundingBox3D` の寸法は cm。** mm のつもりで x 中心 3.4 と書いて、切り取りの相手が体に触れず `ALL_TOOL_BODY_REFERENCE_LOST` になった。エラー文が「相手が無い」と言う時は、相手の位置を疑う
16. **`imshow` に 3 次元配列の断面を出す時は、配列の軸の順（ここは z, y, x）を確かめる。** `occ[:, :, k].T` を「z = k の上から」のつもりで描いたら x = k の断面で、見出しだけが合った図になった。図から結論を出す前に、寸法の分かっている部品（板・すき間の幅）で検算する
17. **自作の検査ツールが出した「欠陥」は、まず CAD の形（STL の境界の数値）と照合する。** 尾の端に「厚さ 1.6 mm の刃とくさび」が出たが、ボクセル化の不具合（箱の x の始点が固体の端より右にあると、負の添字のスライスで行が全部埋まる）の人工物だった。CAD を切って直した後に、箱の始点を変えても結果が変わることで気づいた。**箱の位置・大きさを変えて結果が変わらないことを、検査の確認項目にする。** 直した CAD の変更は元に戻した（フィーチャの削除）
18. **静止姿勢の検査は、動く関節の安全の証拠にならない。** 同心ナックルの 4 mm 一定は玉と椀の間だけで、脇の V は曲げると初めて出た。角度を変えた姿勢（p1〜p5）で見てはじめて分かった

# Lessons — Design Run DESIGN-2026-09-29-01

1. **1 つの作業ツリーで 2 つの Agent が別ブランチを使うと、HEAD を取り合う。** Design と Engineering が同じ `serpens/` で checkout し合い、
   Engineering の 2 コミットが main に入った（ENTRY-0004）。Agent ごとに `git worktree` を分けるのが安全。共有の状態ファイル（ai-shared）は未追跡のまま共有ツリーに置く
2. **Fusion の API スクリプトに日本語の文字列リテラルを書くと文字化けする**（UTF-8 が別の符号として読まれ、名前の比較が失敗・外観の色が付かない）。
   外観はライブラリの id（例 `Prism-127` = プラスチック マット白）で取り、名前は ASCII にする
3. **Fusion の as-built ジョイントが動かない時は `isGroundToParent` を見る。** 最初に作ったコンポーネントが親に固定されていて、別の節を固定すると間の関節が全部動かなくなった
4. **センサーの位置を顔の造作に割り当てるときは、光の通り道まで計算する。** 眉のライン光を顔の面から 10 mm 下げる案は、鼻先が近い床（38〜48 mm）への光を遮っていた（側面視の計算で発見）
5. **2D の図より、3D で横から見ると印象が変わる。** 背板を胴より 2 mm 厚くしただけで「屋根の板」に見えた。形の判断は Fusion の側面・正面でも確かめる
6. **関節の隠し方は、中の部品の持ち主（どちらの節と一緒に回るか）まで決める。** 同心ナックルは形だけなら成立するが、関節の後ろの空間の持ち主が変わり、電装の位置と衝突した（ENTRY-0011）
7. **Fusion の正投影カメラ: 透視から切り替えた直後の 1 回目は `viewExtents` が無視される**（画面いっぱいに 1 色の絵になる）。カメラを 2 回代入し、`vp.camera.viewExtents` を読み返してから保存する
8. **Fusion の MCP は 1 回の呼び出しで描き出し 30 枚前後を超えると時間切れになる。** 時間切れでもスクリプトは最後まで走ることがあるので、ファイルの時刻で確かめてから再実行する
9. **自分で作った評価モデルは、図にして形を確かめてから数値を採る。** J1 の 2D 検討で、首の前面・首の上の切り方・角度の折り返しの誤りを図で 3 回見つけた
